# Sakura VoiceNote 仕様差分（現行 v0.1.2 固定 → v0.2.0）

## 1. 文書情報

- 文書名: Sakura VoiceNote 仕様差分（現行 v0.1.2 固定 → v0.2.0）
- 作成日: 2026-05-31
- 対象プロジェクト: `Sakura VoiceNote`
- 参照元（固定対象）: 現行 `v0.1.2` ソース一式
- 目的: `v0.1.2` を変更せず、`v0.2.0` を別途作成するための差分定義

---

## 2. 開発前提（重要）

### 2.1 現行ソース固定

- 現行 `v0.1.2` のソースは**凍結（Fix）**する。
- バグ修正を含め、`v0.1.2` への機能変更は行わない。
- 仕様変更はすべて `v0.2.0` 側で実施する。

### 2.2 v0.2.0 は別途作成

- 実装は `v0.1.2` を参照して新規作成する。
- 履歴混在を避けるため、ブランチまたは別ディレクトリで管理する。
- `v0.2.0` の目標は「配布容易性（ライセンス・運用負荷の低減）」を優先する。

---

## 3. 変更方針（v0.2.0）

1. `ffmpeg` 同梱依存を排除する。
2. `faster-whisper` / `PyAV` / 同梱モデルを標準構成から外す。
3. 文字起こし経路を「字幕優先 + クラウドSTTフォールバック」に再設計する。
4. 出力品質よりも、配布しやすさ・説明しやすさ・保守しやすさを優先する。

### 3.1 採用決定（2026-05-31）

- 採用方式: **方式1（クライアント直API方式）**
- API利用方針: 字幕なし動画はクラウドSTT/APIで処理する
- 依存方針: **ffmpeg 同梱を廃止**（`av.libs` を含む再配布を行わない）
- 現行固定: `v0.1.2` は凍結し、`v0.2.0` を別途作成する

---

## 4. 差分一覧（現行 → 変更後）

| 項目 | 現行 v0.1.2 | v0.2.0 変更後 |
| --- | --- | --- |
| 音声処理基盤 | `faster-whisper` + `PyAV(av)` + FFmpeg系DLL同梱 | 標準構成から除外 |
| モデル同梱 | `resources/models/faster-whisper-tiny` 同梱 | 同梱廃止 |
| 字幕なし時 | ローカル音声抽出→Whisper | クラウドSTTへフォールバック |
| 依存方針 | ローカル推論依存あり | API依存中心（軽量構成） |
| 配布物サイズ | モデル・ネイティブDLLで大型化 | 軽量化 |
| ライセンス説明 | FFmpeg再配布説明が必要 | FFmpeg再配布説明を不要化（標準構成） |
| オフライン性 | 高い | 低い（ネット接続前提） |
| 初回導入難易度 | 高め（同梱物多い） | 低め（構成単純） |

## 5. 機能要件差分

### 5.1 変更する機能

#### F-02（取得方式）

- **現行**: 字幕取得不可時、音声抽出→ローカル文字起こしへ自動遷移。
- **v0.2.0**: 字幕取得不可時、クラウドSTTへ自動遷移。

#### F-03（文字起こし）

- **現行**: ローカルWhisper経路あり。
- **v0.2.0**: ローカルWhisper経路を削除し、API経路に統一。

#### F-06（出力保存）

- 出力ファイル命名規則（`<timestamp>_*`）は維持。
- `metadata.json` に `transcript_source` として `subtitles` / `cloud_stt` を記録。

### 5.2 廃止する機能

- ローカルモデルによる音声文字起こし（`faster-whisper` 経路）
- `resources/models/faster-whisper-tiny` 同梱配布

## 6. 音声ダウンロード（mp3）に関する仕様判断

### 6.1 結論

- **音声だけをダウンロードすること自体は、ffmpeg なしでも可能**。
- ただし、**常に mp3 へ変換して保存することは、ffmpeg なしでは原則不可**（または実装/保守コストが高い）。

### 6.2 理由

1. `yt-dlp` は音声ストリームの取得（ダウンロード）自体は可能。
2. しかし、`m4a/webm/opus` 等を `mp3` に変換するには、通常は ffmpeg 相当のトランスコード基盤が必要。
3. 元動画側の音声が最初から mp3 の場合のみ、変換なしで mp3 保存できる可能性がある（一般的ではない）。

### 6.3 v0.2.0 の採用仕様（推奨）

- 仕様としては **「音声のみダウンロード（原形式維持）」** を採用する。
- `mp3固定` は標準要件にしない。
- STT入力は `m4a/webm/mp4` など API が受け付ける形式を優先する。

### 6.4 どうしても mp3 固定が必要な場合

- 次のいずれかを別要件として扱う。
  1. ffmpeg を外部前提（ユーザー環境準備）で利用
  2. サーバー側で変換（クラウド処理）
- `v0.2.0` 標準スコープには含めない（配布容易性優先のため）。

## 7. 依存関係差分（想定）

### 7.1 削除候補

- `faster-whisper`
- `av`
- （ローカル推論にのみ必要な周辺依存）

### 7.2 維持候補

- `yt-dlp`
- `python-dotenv`
- `openai`（または採用するクラウドSTT/LLM SDK）
- `deep-translator`（翻訳フォールバックを残す場合）

### 7.3 ビルド差分

- PyInstaller の `--collect-all faster_whisper/ctranslate2/tokenizers/av` を削除。
- モデル同梱 `--add-data resources/models/faster-whisper-tiny` を削除。

---

## 8. 非互換事項

1. オフラインでの字幕なし動画処理は不可（ネットワーク必須）。
2. `mp3 固定出力` は保証しない（原形式優先）。
3. APIキー未設定時の字幕なし動画は処理不可とし、理由を明示して終了する。

---

## 9. 受け入れ基準（v0.2.0）

1. 字幕あり動画で、従来どおり文字起こし・要約ファイルが出力されること。
2. 字幕なし動画で、APIキー設定時はクラウドSTT経由で出力されること。
3. 字幕なし + APIキー未設定時、ユーザーが次アクションを判断できる明確なエラーメッセージを表示すること。
4. 配布物に `ffmpeg` / `av.libs` / 同梱Whisperモデルが含まれないこと。
5. `metadata.json` に `transcript_source` が正しく記録されること。

---

## 10. 実装着手順（推奨）

1. `v0.1.2` をタグ/ブランチで固定。
2. `v0.2.0` 作業ブランチ（または別ディレクトリ）を作成。
3. 依存整理（削除・追加）を実施。
4. `pipeline.py` を「字幕→クラウドSTT」構成へ置換。
5. `scripts/build_windows_installer.ps1` の同梱指定を整理。
6. `README.md` / `操作マニュアル.md` / `試験項目書.md` を v0.2.0 用へ更新。
